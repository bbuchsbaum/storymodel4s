The `embed-core` module supplies portable embedding contracts and two free local baselines. This
example covers two jobs:

1. create deterministic hashed n-gram vectors for public text; and
2. check a sanitized request against a named remote-use policy.

The policy check produces an authorization value. It performs no network call.

## Read the batch result

`HashedNgramEmbedder` uses a fixed dimension and seed. Those settings appear in the provider and
geometry identities. Repeating the batch with the same settings and text produces the same vector.

The batch returns one `EmbedOutcome` per request. The story line produced a checked 32-dimensional
unit vector. The blank line produced `Missing(OutOfVocabulary)`. The missing item remains in the
batch result beside the successful item. The attempt receipt records one local provider call and a
plain digest because both inputs were marked `Public`.

This baseline represents character and word overlap. Its deterministic output makes it useful for
tests and reproducible candidate generation. The example supplies no evidence that it improves
alignment accuracy or should serve as a production semantic model.

## Check a remote request

The second half begins with source text containing a synthetic name. A closed whole-word detector
certifies its span. `PseudonymizedText.checked` verifies the replacement and records a keyed digest.
`RemotePolicy.evaluate` then checks the payload, provider, model, purpose, detector configuration,
token budget, and validity window together.

The output shows three decisions:

- a raw sensitive payload is denied;
- a sanitized payload submitted for an unlisted purpose is denied; and
- the same sanitized payload is authorized for `candidate-retrieval` with a 12-token budget and an
  expiry time of `61000`.

The authorized request's public rendering replaces the payload with `<redacted>`. The capability
carries a keyed payload digest, policy identity, provider and model identities, purpose, budget,
expiry, and detector identity.

`SensitiveKeyProvider.static` stores one key in memory and is intended for tests and examples.
Production code supplies a store-local implementation backed by an appropriate secret store.

## Provider adapters

The JVM-only ONNX sentence encoder implements the `Embedder` interface. It accepts an `EmbedBatch`
and returns a `BatchResult` with per-item outcomes and embedding receipts.

The grakern adapter has a different job and a different interface. `GrakernStructuralDistance`
implements `StructuralDistance` over proposition evidence. Its `EmbeddingSpace` names the
structural channel, and its memoized query rows produce `EmbeddingReceipt` and `ProviderCall`
records. It does not implement `EmbedBatch`, `RemotePolicy`, or `EmbeddingCache`.

Provider evaluation and calibration remain separate work; this guide establishes API behavior
only.
