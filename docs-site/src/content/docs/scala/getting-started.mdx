storymodel4s compares a story with a later recall. A `StoryModel` records the people, events,
claims, contexts, and order in the story. A `RecallGraph` divides the recall into units. `GraphHsmm`
assigns each recall unit probability mass over story nodes and named external states such as an
association or commentary.

The program returns typed values that you can inspect. You can read every posterior row, the most
likely route, the mass assigned inside and outside the story, and summaries such as coverage,
specificity, and compression. Story and recall records cite exact text. Support-aware estimates
keep their support, and unavailable estimates remain unavailable.

Today the analysis starts from an existing `StoryModel`. The repository includes a reviewed model
of *The War of the Ghosts*, which the example below uses. The software that builds a complete model
from arbitrary prose is under development.

## What this program does

The program follows five steps:

1. load a story model with 71 situations and 84 alignable nodes;
2. divide a short recall into two units;
3. generate 86 sparse candidate matches with a free word-overlap baseline;
4. infer a partial alignment with `GraphHsmm`; and
5. compute a `RecallSignature` with support-aware summaries.

The input recall says:

> One of the men with him got hit by an arrow and they lifted him into the boat.

The comparison returns one probability row for each recall unit. Each row distributes mass across
story nodes and explicit external states.

## Run it

storymodel4s currently runs from a source checkout. You need JDK 17 or 21, sbt 1.12.14, and a local
checkout of the pinned `grakern` dependency.

```sh
git clone https://github.com/bbuchsbaum/storymodel4s.git
cd storymodel4s
```

Save this exact program as `fixtures/src/main/scala/docsprobe/PublicAlignAndInterpret.scala`:

Run it with:

```sh
sbt -Dstorymodel4s.grakern.build=/absolute/path/to/pinned-grakern \
  "fixturesJVM/runMain docsprobe.alignAndInterpret"
```

## Read the result

The recorded run printed:

<pre><code>{output}</code></pre>

<AlignmentMassFigure />

The first recall unit assigns 46.08% of its mass to the story. Its strongest source match is the
event in which a young man says that he has no arrows. The second unit assigns 2.09% to the story
and 97.91% to external states.

Those results are poor because the free baseline compares word overlap and has no model of
synonyms. The recall is a faithful paraphrase, yet the baseline sends most of it outside the story.
This run establishes the public workflow and the shape of its output. Accuracy requires separate
calibration evidence.

The summary reports uniform coverage of `0.0067`. Importance-weighted coverage is `n/a`: zero of
the 71 eligible situations carried an importance weight. Specificity and compression each report a
value and support of `0.2409`, the source mass that contributed to the estimate.

## What you can inspect

| Accessor | What it returns |
| --- | --- |
| `result.posterior.rows` | one probability row for each recall unit |
| `row.mapSource` | the row's highest-probability source node, when one exists |
| `row.sourceMass` | the row's total mass on story nodes |
| `row.externalMass` | the row's total mass on external states |
| `result.viterbi` | the inferred route through source and external states |
| `signature.uniformCoverage` | coverage across the story's alignable situations |
| `signature.importanceWeightedCoverage` | weighted coverage, conditioning weight, and observed count |
| `signature.specificityMass` | specificity and the source mass that supports it |
| `signature.compression` | compression and the source mass that supports it |
| `signature.externalMass` | attributed external mass and unranked mass as separate values |

The replay gate compiles this exact program against revision <code>{PRODUCER_REVISION}</code>, runs
it on the JVM, and compares stdout byte-for-byte with the displayed output. The result is
conditional on the heuristic segmentation used in the program.
