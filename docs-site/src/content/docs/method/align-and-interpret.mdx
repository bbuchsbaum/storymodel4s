The previous page shows what the representation **preserves**. This one shows the
machinery **running**: a complete program that takes a recall transcript, aligns it
against a story model, and computes a recall signature.

It imports nothing but public `storymodel4s` API. No test sources, no copied internal
helpers, no demonstration facade written to make the page work. That constraint was
not a stylistic preference — it was the measurement. Before this guide existed we did
not know whether an ordinary consumer *could* drive the library end to end, and the
honest way to find out was to try it and let it fail if it was going to.

It did not fail. Nothing was added to the library to make this page possible.

## Reading it straight

**The structure is found.** 71 situations, 84 alignable nodes, 2 recall units, 86
surviving sparse candidates. The recall is short — a precise paraphrase — and both of
its units get a MAP anchor: unit 0 lands on `ym1-says-no-arrows`, the young man's
statement about arrows, and unit 1 on the canoe's arrival.

**And the alignment is poor.** Look at the mass rather than the anchors:

| | unit 0 | unit 1 |
| --- | --- | --- |
| source mass | 0.4608 | 0.0209 |
| external mass | 0.5392 | 0.9791 |

Unit 1 is 98% external. The model is saying that almost none of that recall unit is
attributable to anything in the source, and it is right to say so: `lexicalJaccard` is
a bag-of-words baseline with no synonymy, so a paraphrase that says the same thing in
different words looks like new material. `uniform coverage: 0.0067` is the same fact
from the other end — essentially none of the story's 71 situations was recovered.

**None of that is a bug, and none of it is a good result.** It is a deterministic,
dependency-free baseline doing exactly what a deterministic, dependency-free baseline
does. It exercises the whole pipeline and it is not a quality claim. A quality claim
needs a declared semantic provider and its own evidence, which this page does not have
and does not pretend to.

## The line worth the whole page

```
importance-weighted coverage: n/a (conditioning weight 0.0000; coverage 0/71)
```

The library was asked for a number it could not support, and it declined — then
printed the conditioning mass that made it decline, so you can check the refusal
rather than take it on faith.

A system built to look good here would have returned `0.0`. That would be a *number*,
it would sit neatly in a table, it would average with other numbers, and it would be
false: zero coverage and unmeasurable coverage are different findings, and the second
one is the one that happened. Everything else on this page is downstream of that
distinction.

`specificity: 0.1747 (support 0.2409 = 0.4817/2.0000)` shows the same discipline in
its other mode. The value is published *with* the mass conditioning it, so a reader
can see that it rests on about a quarter of the available support and weigh it
accordingly, instead of receiving `0.1747` as though it were solid.

## What this does not show

This is one of six workflows the documentation owes you. It does not cover typed
acquisition, autobiographical-interview scoring, canonical persistence, or the output
bundle. It uses the hand-authored *War of the Ghosts* fixture, not arbitrary prose —
the library does not yet turn a raw story into a complete model unattended, and no
page here should imply otherwise.
