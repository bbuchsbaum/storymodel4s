This example compares a recall with the reviewed *War of the Ghosts* story model. It performs five
steps:

1. load the story model;
2. divide the recall transcript into recall units;
3. generate sparse candidate matches with lexical Jaccard distance;
4. infer an alignment with `GraphHsmm`; and
5. summarize the alignment with `RecallSignature`.

The program imports public `storymodel4s` APIs. It uses no test helpers or copied internal code.

The program found two recall units and retained 86 sparse candidates. Each posterior row divides its

| --- | --- | ---: | ---: |
| 0 | `ym1-says-no-arrows` | 0.4608 | 0.5392 |
| 1 | `sc1c-canoe-arrives` | 0.0209 | 0.9791 |

The displayed node is the most probable source node within the row. External states carry more total
mass for both units. Unit 1 is especially clear: the model assigns 97.91% of its mass outside the
source.

The input recall is a faithful paraphrase. Lexical Jaccard compares word overlap and has no synonym
model, so it performs poorly here. This run establishes that the public workflow executes and shows
how the result is represented. It provides no evidence of calibrated alignment accuracy.

## Read the summary with its support

`RecallSignature.compute` produces several estimates from the posterior.

### Uniform coverage

The result is `0.0067`. For each story situation, the implementation accumulates the posterior mass
that reaches it and applies `1 - exp(-mass)`. It then averages those 71 values. A short recall that
reaches few situations therefore produces a small value.

The console output rounds each row total and omits the posterior for individual leaves. Recomputing
the exact coverage value requires the original result object.

### Importance-weighted coverage

The program prints:

```text
n/a (conditioning weight 0.0000; coverage 0/71)
```

The fixture supplies no importance weights for the 71 situations. `RecallSignature` returns an
unavailable estimate and reports the missing conditioning weight. A numeric zero would mean that
the estimate was supported and its measured value was zero; this run supports no such measurement.

### Specificity and compression

Specificity is `0.1747` and compression is `0.0714`. Each value carries support of `0.2409`, computed
from `0.4817` source mass over two recall units. The support tells a reader how much of the recall
contributed to each estimate.

### External mass

The result attributes `0.7591` of the posterior to external content. All ranked external mass was
classified; the output reports `unranked=0.0000` and `ranked=1.0000`.

## Scope of this result

The story structure comes from the hand-authored acceptance fixture. The run uses a deterministic,
dependency-free lexical baseline. A semantic encoder would require its own identity, receipt, and
quality evidence. The producer used one JVM and Java 25.0.1, so this archived run establishes no
Scala.js, Scala Native, JDK 17, or JDK 21 result.
