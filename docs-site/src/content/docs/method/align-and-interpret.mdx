The previous page shows what the representation **preserves**. This one shows the
machinery **running**: a complete program that takes a recall transcript, aligns it
against an already-built story model, and computes a recall signature.

It imports nothing but public `storymodel4s` API — no test sources, no copied internal
helpers, no demonstration facade written to make the page work. That constraint was the
measurement. Before this guide existed we did not know whether an ordinary consumer
*could* drive the library end to end, and the honest way to find out was to try and let
it fail. It did not fail, so nothing was added to the library to make this page possible.

## Reading it straight

**The structure is loaded, not discovered.** 71 situations and 84 alignable nodes come
from the hand-authored *War of the Ghosts* model, which the program builds before it
aligns anything. The run does not recover that structure from text and nothing here
should be read as evidence that it could.

What the run actually does is map 2 recall units onto that structure, from 86 surviving
sparse candidates. Both units get a MAP anchor: unit 0 on `ym1-says-no-arrows`, unit 1 on
the canoe's arrival.

**The mass is where the result lives.**

| | unit 0 | unit 1 |
| --- | --- | --- |
| source mass | 0.4608 | 0.0209 |
| external mass | 0.5392 | 0.9791 |

Unit 1 is 98% external — the model attributes almost none of it to anything in the
source. Under `lexicalJaccard`, a bag-of-words distance with no synonymy, that is the
*expected* behaviour for a paraphrase that says the same thing in different words. Expected
is not the same as correct: this is a semantically faithful paraphrase, so a mostly-external
verdict is the baseline's limitation showing, not a property of the recall.

**`uniform coverage: 0.0067` is a mean, not a tally.** It is mean posterior leaf
visitation — `leaves.map(visitation).sum / leaves.size` — so it is structurally bounded by
how much source mass exists to spread over 71 leaves. Here total source mass is
`0.4608 + 0.0209 = 0.4817`, and `0.4817 / 71 = 0.0068`, which is the printed figure. A
2-unit recall against a 71-leaf story has a ceiling of `2/71 = 0.0282` even under perfect
alignment, so this run sits at roughly a quarter of what was attainable. That is a poor
result. It is not "almost nothing was recovered", and reading the number that way would
mistake a short recall for a failed alignment.

## The line worth the whole page

```
importance-weighted coverage: n/a (conditioning weight 0.0000; coverage 0/71)
```

The library was asked for a number it could not support, declined, and printed the
conditioning mass that made it decline, so you can check the refusal rather than take it
on faith.

A system built to look good returns `0.0` there. That would be a *number*: it sits in a
table, it averages with other numbers, and it is false, because zero coverage and
unmeasurable coverage are different findings and the second one is what happened.

`specificity: 0.1747 (support 0.2409 = 0.4817/2.0000)` shows the same discipline in its
other mode. The value is published *with* the mass conditioning it, so a reader can see it
rests on about a quarter of the available support and weigh it accordingly, instead of
receiving `0.1747` as though it were solid.

## What this does not show

This is one of six workflows the documentation owes you, and the guide is still missing an
accessible static figure. It does not cover typed acquisition, autobiographical-interview
scoring, canonical persistence, or the output bundle. It uses the hand-authored *War of the
Ghosts* fixture, not arbitrary prose — the library does not yet turn a raw story into a
complete model unattended, and no page here should imply otherwise.
