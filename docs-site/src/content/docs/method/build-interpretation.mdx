A complete story model needs more than sentence boundaries. A program must represent what each
sentence says, keep competing analyses when the evidence does not settle them, and connect mentions
of the same person or object across sentences.

storymodel4s provides public types for those three stages. The examples below run each stage in
isolation. The unattended pipeline that joins them for arbitrary prose is still under development.

| Stage | Input | Result you can inspect |
| --- | --- | --- |
| Local meaning | checked PENMAN | concepts, roles, polarity, embedded content, reentrancy |
| Resolution | evidence-backed proposals | accepted value, alternatives, unresolved reason, or rejection |
| Document identity | sentence-local charts and mention pairs | preserved charts plus deterministic coreference clusters |

## Read one proposition graph

This program parses a small PENMAN graph, validates and canonicalizes its AMR roles, then converts it
to the library's local `PropositionChart`.

It prints:

The result has seven concepts and eight relations. `man` is shared by several roles, so it remains
one reentrant concept. The negative polarity belongs to `feel`, while the embedded `hit` proposition
sits under `say` as speech content. The source digest records the imported graph; the chart checksum
records the canonical local representation.

## Keep disagreement visible

Parsers and agents submit proposals with evidence and call receipts. A deterministic resolver applies
the selected acceptance policy.

<pre><code class="language-scala">{acquire}</code></pre>

<pre><code>{acquireOutput}</code></pre>

The same result type carries four scientifically different outcomes:

- two agreeing providers plus a named calibration produce `Accepted`;
- disagreement produces weighted `Alternatives`;
- one proposal under the conservative policy produces `Unresolved`;
- a structural failure produces `Rejected`.

`Unresolved` means the available evidence did not establish one answer. `Rejected` means the proposed
value failed a rule. Downstream code can distinguish those cases directly.

## Connect mentions across sentences

Sentence-local charts retain their own nodes. `MentionTable` gives selected nodes typed mention IDs,
and `CorefPartition` records exact identity across sentences.
